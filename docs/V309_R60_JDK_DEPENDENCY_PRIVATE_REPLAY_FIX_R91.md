# R91 original-JAR replay hardening for R60

The original v309 settings-save method reads `java/nio/file/StandardCopyOption.REPLACE_EXISTING` through `getstatic`. The original JAR does not embed the JDK's `StandardCopyOption.class`, and should not. R60 previously scanned **all** external `getstatic/putstatic` owner classes of every ordinary owner method and mistakenly required even Java runtime classes to have an archive entry. This prevented legitimate original JAR private source replay, before bounded short-method source analysis could begin. R91 reused the same check and inherited the failure.

R91 repairs both R60's existing replay entry point and R91's integrated replay. A single reviewed pure helper `_private_external_field_owners` excludes external JDK packages (`java/`, `javax/`, `jdk/`) from **JAR-bundled** class requirements while keeping all other external client owner classfiles mandatory. Every static-field owner must still be resolved and every actual short-source field read/write retains the exact `_typed_field` field type, access, and declaration validation. This is a classpath boundary correction, not a relaxation of original JVM source matching. Unit tests check real `StandardCopyOption`-shaped inputs, missing external client owner preservation, duplicate owner handling, and unresolved owners fail-closed.

The original complete client JAR SHA-256 remains pinned. Hosted CI tests are synthetic; complete private R60 and R91 CLI end-to-end replay has not yet been certified. No original source, JAR, key or obfuscated member name is committed.
