# R131 — first directly committed, original-verified v309 Java client source candidate

## The actual source file

This PR intentionally changes the direction from repeated infrastructure-only milestones to a **versioned Java source tree in GitHub**. It adds a small, self-contained Java client source recovered from the user's supplied decompiled source archive, with genuine original-v309 JVM evidence:

`source-candidates/v309/src/rs/runelite/events/ClientStartUp.java`

This path is **provisional**. It does not populate or bypass the existing complete Source Milestone-only canonical `recovered-source/v309/src/` publication policy. It is an original **client-side** event class, not the independently written server/emulator.

The supplied decompiled source originally compiled with **one different `equals(Object)` control-flow branch**. It returned `other.canEqual(this)` directly; that emits `ireturn` where the original client instead branches, returns false on one arm, and returns true on the other. The restored source now expresses the original branch. Readable local/parameter names (`other`, `otherClient`, `ignored`) were also restored and independently demonstrated not to alter the compiled bytecode. Methods are `<init>`, `equals`, `canEqual`, `hashCode`, `toString`.

## Exact private original-v309 proof

The original read-only JAR was SHA-pinned to `ff5a58d9dc2bf7b75d7346aa6b711ebd423435e04c3f4e1f0d1de874c6d08f38`. The restored Java file SHA-256 is `bcb0481037a066a6bc1687160a4d4274743a6581005f487aca070d2750139e7a`. It was recompiled **independently** using `javac --release 9 -g:none -proc:none` with explicitly empty classpath/sourcepath. The original `client.jar` did not enter that compiler invocation, and the original binary was never executed.

For provenance, the source build's verifier metadata is normalized to **the original frame encoding**. This is a metadata-only, source-derived repair and does not copy original method code or transfer live client networking/runtime artifacts.

## What CI actually checks

The public CI cannot access or execute private v309 `client.jar`. It does, however, compile the **actual committed Java source file**, verify the **frozen original 33-instruction symbolic witness SHA**, apply the source-built class's **specifically validated verifier metadata repair**, confirm executable Code bytes are unchanged, and load the repaired class using `java -Xverify:all` on both Ubuntu and Windows. Negative tests reject mutated StackMap preimages, wrong compiled SHA pins, and an occupied output file.

These cross-platform synthetic/public validations are a useful independently repeatable proof of the committed candidate. They do not replace the original private-binary comparison or prove full client behavior. The frozen opcode-manifest digest was generated by a separate read-only original-v309 `javap -p -c -s` inspection.

## Remaining milestones

This is **one actual restored source class**, not a complete deobfuscated client. One class with five methods represents neither the original `rs/` class-set coverage nor package/class namespace legality, external dependencies, client login/render/cache, or semantic member names across the whole client.

Build on the already merged R125–R128 solver infrastructure and the R129/R130 source-first build/rename gates to bring further verified Java source files into `source-candidates/v309/src/`. Promote the whole candidate tree into canonical `recovered-source/v309/src/` **only once all original class/member, zero-project-binary-fallback clean compile, resource manifest, safe isolated runtime and release-rights checks are satisfied** (issue #1004). Future builds must receive their own complete source snapshot and independently pinned original-binary parity acceptance.

Original client JARs, caches, logs, user data and independent server implementations remain outside this GitHub source-candidate lane.
