# Original v311: first 3 independently rebuilt Java classes

**21 October 2026.** This is an actual **offline read-only original-v311 binary ↔ privately reconstructed Java source** experiment, followed by an independent Java 9-target compilation. It is not a claim that the 1,184 project classes have all been recovered. It is intentionally distinct from source-only synthetic GitHub CI.

## Exact original and isolated compilation

- Original private `client(20261021-111920).jar` SHA-256: `5b619b82a8ed976d2051f84cda98815943d1ddb82afac9d49f3126f829101268`.
- Three directly inspected original `rs/` classfiles were found to require **no other project `rs/` class dependency** beyond each class's self-reference. The classfile constant-pool screen found **215 of 1,184** such candidates in this precise version. That is a *candidate count*, not 215 proven source-recoverable classes or a full dependency-closure proof.
- Privately reconstructed Java was compiled using `javac --release 9 -proc:none -g:none -encoding UTF-8` into an empty target directory, with a **separate empty compilation classpath and empty sourcepath**, without any `rs/` binary class or original client JAR on the compiler classpath. Generated classes have major version 53.
- Compare original vs independently compiled private classes using `javap -c -p -s`, canonicalizing **only the numeric constant-pool reference indexes**. Symbolic field/method targets, ordered JVM opcodes, exact byte offsets and branch targets remained comparable. Source/compiler output was kept private.

For the linked-list `rs.t` method, the **source control-flow shape matters**: an empty null branch followed by the non-null action branch compiles to the original `ifnonnull` then `goto` and preserves its exact instruction offsets. The simpler equivalent `if (e != null)` source *does not* compile to that original instruction layout. This is a concrete reason to do independent bytecode comparison rather than regard successful compilation as source recovery proof.

## New reusable GitHub recovery verifier

`src/spk_recovery/standalone_source_parity.py` and the existing
`spk-recovery` CLI now support a bounded, independent compiler replay. Given
private candidate Java under `<source-root>/rs/...`, run:

```powershell
spk-recovery verify-standalone-source `
  C:\private\client-v311.jar C:\private\v311-recovered-src `
  --original-sha256 5b619b82a8ed976d2051f84cda98815943d1ddb82afac9d49f3126f829101268 `
  --class-sha256 rs/t.class=430c61233ef1d46a3dadbe4947a3d4d17019db2bc1d4678dc732623ea1b3274f `
  --class-sha256 rs/k/a.class=e47b1cdcfde0e318b0dafcec9c25b88d9c9f305555d888c95e5f9c1dc0da0281 `
  --class-sha256 rs/plugins/f.class=86b4eb3640bfdeb56ac726b977caff1bac6139c035cdaab22a2a05c8d488dd32 `
  --out-dir C:\private\v311-first-sources-evidence
```

The tool validates the **whole original JAR SHA and each individual class SHA before creating any output**, rejects ambiguously duplicate ZIP entries, symlinked/missing source files, conflicting classes generated by `javac`, wrong Java 9 class major version, and divergences in declarations or ordered disassembled Code instructions. It never points `javac` at the original JAR; the only input Java source files are the explicitly selected local candidates. It refuses an existing output directory and never writes success evidence for failed compilation/parity. The resulting JSON records SHA fingerprints and counts, **not raw source or game class bytecode**.

GitHub CI runs the same underlying process with privately unrelated **synthetic, JDK-only Java classes**. Those CI tests check successful compilation plus the important negative paths; **hosted CI does not have the three real private source candidates or the original client JAR** and cannot independently repeat these specific original-v311 observations.

## Strict scope of the result

**Supported:** three original class declarations and 47 instructions are consistent with independently compiled Java 9 bytecode, including symbolic operands and branch layout, after replacing numeric constant-pool indexes. This is stronger than pure class-role/source guessing.

**Not established:** exact original source formatting, full classfile byte identity, every attribute (including StackMapTable, signatures, annotations or `ConstantValue`), complete external dependency closure, game-runtime behavior, graphical performance, source-compilable 1,184-class v311 release, or original-v309 → v311 member lineage transfer.

No original client binary, reconstructed Java source, private compilation output or decompiler artifact was added to GitHub. The next source milestone should **expand actual independently compiled source islands and prove wider class/member equality** while respecting the separate complete-source release gates.
