# R216 — offline asset safety and accurate startup messages

Continued the private v309 source-built client from R215. In real production Java classes `AssetUpdaterManager`, `CacheUpdater`, `SpriteUpdater`, `ConfigUpdater`, the **opt-in** `-Dspk.offlineProbe=true` mode now (a) checks local asset versions instead of treating remote unavailability as corruption, (b) explicitly reports absent local versions, and (c) prevents cache/sprite/config download methods from touching local directories before network skip checks. Offline mode no longer prepends generic 'Error with the sprite updater' when the exact problem is absent local version. Normal non-probe production paths were preserved.

**Full compilation:** all **1,275** Java sources, `javac --release 11`, **zero errors**, **1,376** classfiles. All **10/10** existing offline application checks passed with local original-v309 resources; separate regression passed for absent local version, valid local version, and blocked cache/sprite/config downloads. Controlled Linux virtual-display launch reached plugin initialization; no fatal startup exception in 11-second probe; intentionally terminated by timeout. It logs `Offline probe: local Sprites asset version is missing; download skipped.` rather than a false remote-version corruption message. This does **not** establish complete network isolation, graphics parity or successful gameplay.
